# 포트폴리오 앱 통합 수집기

기존 앱: https://dh-portfolio-desk.drkim7.chatgpt.site

앱을 주 화면으로 사용합니다. 이 수집기는 GitHub Actions에서 실행하고, 암호화한 결과만 Pages에 게시합니다. 앱의 ‘수집 결과 연결’에서 주소와 비밀번호를 입력하면 파일 다운로드·가져오기 없이 시세와 일봉을 반영합니다. 연결한 탭이 보이는 동안 15분마다 확인하고, 새로 열면 비밀번호를 다시 입력합니다. 비밀번호는 앱 서버에 보내거나 저장하지 않습니다.

## 설치
1. GitHub 저장소에 pipeline.py, test_pipeline.py, holdings.example.json, .gitignore를 추가합니다. daily.yml은 반드시 `.github/workflows/daily.yml` 위치에 둡니다. 실제 holdings.json은 올리지 마세요.
2. 기존 앱 설정에서 JSON을 내보내고 그 내용을 저장소 Settings → Secrets and variables → Actions → `HOLDINGS_JSON` Secret에 넣습니다. 실제 앱의 items/rate/limits/baseLimit 형식을 그대로 받습니다.
3. `REPORT_PASSWORD` Secret에 길고 고유한 비밀번호를 설정합니다(최소 8자). 승인된 공공데이터 키가 있다면 `DATA_GO_KR_KEY` Secret에 등록합니다. 키를 코드·로그에 쓰지 마세요.
4. Settings → Pages → Source를 GitHub Actions로 지정합니다. 저장소의 Actions 쓰기 권한도 허용해야 합니다.
5. Actions에서 ‘보유 종목 점검’을 수동 실행합니다. 성공 후 표시되는 Pages 주소를 기존 앱 ‘수집 결과 연결’에 입력하고 비밀번호를 넣습니다.
6. 첫 실제 실행에서 성공/실패 수와 국내·미국 기준일을 확인하세요. 이 묶음은 모의 네트워크 검증을 통과했지만 실제 제공사 호출 성공을 보증하지 않습니다.

## 운영 기준
- 월~금 한국 16:40, 토요일 07:40 예약입니다. GitHub 실행은 정시 보장이나 거래소 휴장일 자동 제외가 아닙니다.
- 앱 패치는 시장 현지 날짜의 당일 봉을 제외하므로 장 마감 직후 리포트보다 하루 늦을 수 있습니다. 날짜를 상단에서 확인하세요.
- 마감 시각은 정규장 기준이고 특별 개장일·미국 조기 폐장일은 별도 반영하지 않습니다.
- 공공데이터 이력이 있으면 그 이력을 유지하며 Yahoo 이력을 섞지 않습니다. 분할·배당 등 가격 조정 기준이 다른 데이터를 이어 붙여 가짜 신호를 만드는 것을 피합니다. 최신성이 떨어질 수 있습니다.
- 시세는 종목별 한 번 수집하고 앱에는 계좌별 원래 id로 전달합니다. 앱의 최신 수량·평단·계획·메모를 덮어쓰지 않습니다. id/코드가 변경됐다면 Secret도 다시 내보내 갱신하세요.
- 수집기 리포트의 수량·비중은 Secret에 넣은 시점의 보유내역입니다. 매매 후 최신 JSON으로 교체해야 합니다. 앱과 수집기 보유내역의 자동 양방향 동기화는 아닙니다.
- 거래량 누락은 0으로 바꾸지 않고 관련 거래량 배수 계산을 보류합니다. 짧은 이력을 252일 돌파선으로 표시하지 않습니다.
- 동일 종목의 계좌별 이탈가가 다르면 보조 리포트는 가장 높은 선으로 조기 점검합니다. 계좌별 판단은 앱에서 확인하세요.
- 공개되는 파일은 암호문이어도 내려받아 비밀번호 추측을 시도할 수 있습니다. 강한 비밀번호를 쓰세요. 상태도 암호화합니다. 보유내역·키는 저장소에 커밋하지 마세요.
- 이전 버전에서 평문을 올렸다면 현재 파일만 지워도 Git 기록·기존 배포물에는 남을 수 있습니다. 공개 이력·아티팩트를 확인하고 노출된 키는 폐기/재발급하세요.

## 검증
`python3 -m unittest test_pipeline` (cryptography 필요). 앱 저장소의 `node scripts/check-collector-integration.mjs`는 Python 암호문을 실제 앱에서 복호화·검증하고 지표를 대조합니다.
